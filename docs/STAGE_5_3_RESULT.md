Безопасная схема включает enum категории/направления/ошибки, проверенный код Status, числовые Message ID/Presentation Context/PDU length, ограниченный список стандартных SOP Class/Transfer Syntax UID, конечные значения SCU outcome и Boolean, числовые диагностические счётчики. Неизвестное или не прошедшее проверку значение исключается. Совпадение числового значения с внешним идентификатором само по себе не доказывает анонимизацию: интерфейс прямо не обещает юридическую анонимность.

Экспорт не меняет оригинальные записи. Существующая политика исключения нескольких явно именованных PHI-ключей при первоначальном приёме события сохранена; полный экспорт означает оригинальные **сохранённые** поля, а не восстановление ранее отфильтрованных данных. Старые файлы при чтении не переписываются. Полный текст явно предупреждает о возможных персональных данных, включая диагностические рекомендации и сообщения exceptions. Сохранены краткий/подробный режимы, светлая тема, метки SCU-1/SCP-1; дополнительных фильтров нет.

## Надёжность и точность статусов

Сетевой producer не делает дисковый I/O и не ожидает свободного места в очереди. Admission защищён короткой общей блокировкой, retained события пишутся одним writer в порядке admission, а не wall-clock timestamp. Capacity по умолчанию — 10000 событий и 32 ожидающих управляющих команды. Критическое событие может вытеснить только ожидающее некритическое Write; оно никогда не вытесняет control или другое critical. Если очередь заполнена critical, новое critical отклоняется с отдельным счётчиком. Невозможная гарантия «ни одного потерянного critical» не даётся.

Health различает Active, Degraded, Write Failed, Stopping, Stopped. Отдельно учитываются overflow, неподтверждённая запись, критические подмножества, события после остановки, read failures и control rejection/timeout/failure. Неподтверждённая запись не равна доказанному отсутствию байтов: append мог завершиться частично. Команды Clear/Flush используют acknowledgement; timeout не выдаётся за завершение, команда может исполниться позже. UI больше не сообщает оптимистическое «очищен» до результата. Штатный shutdown прекращает admission и дренирует очередь без вытеснения событий специальным poison item. Неожиданное завершение writer завершает ожидающие acknowledgements и публикует отказ.

Ошибки и потери отображаются компактным раскрываемым предупреждением. Сырая локальная причина ошибки может содержать персональные данные и не входит в safe export. Диагностический TSV-маркер сохраняет накопленные счётчики при доступном диске; после перезапуска восстанавливается последний записанный marker. Accepted/persisted относятся к текущему экземпляру logger. Исторические потери не исчезают после восстановления диска или очистки. Возвращаемый false из Flush/shutdown может означать известную историческую потерю, даже когда retained очередь уже полностью записана.

Ротация сохраняет канонические active + 4 rotated файла по 5 MiB. Запись больше лимита получает явный отказ вместо бесконечного роста. Старейший файл временно перемещается в `.rotation-retained`, удаляется по retention только после успешных canonical moves; при ошибке выполняется обратный rollback без замены файлов. После прерывания backup читается, показывается warning, автоматического удаления нет. Pending backup блокирует следующую ротацию; нужны ручная проверка файлов и осознанная очистка. Временно может сохраняться дополнительный файл сверх обычного retention. Это не транзакция файловой системы с гарантией при потере питания.

Формат старых 9/10-column TSV и имена rotations сохранены; новые строки обратимо экранируют CR, tab, newline и внутренние разделители. Ошибочные старые строки остаются на диске и отмечаются read failure. У старого короткого ID невозможно доказать принадлежность одной ассоциации: такие записи консервативно разделяются, подтверждённый код отдельного RSP сохраняет смысл. Современные unique UID продолжают группироваться. SCU completion теперь записывает Expected File Outcomes для своей ассоциации; отсутствие/несовпадение ожидаемого количества даёт общий Unknown, не отменяя подтверждения отдельного файла. Это касается также старых журналов 5.2 без нового счётчика и неполного cache.

## Ограничения и ручная проверка

- Экспортирует оперативную выборку до 2000 событий, а не всю дисковую историю. Preview показывает до 60000 символов с уведомлением; файл содержит полный выбранный snapshot. Переключение mode не должно использовать устаревший snapshot полного текста как безопасный.
- Полные export-файлы остаются в приватном cache приложения до удаления Android/приложением. При ручной отправке получатель получает read URI permission и может сохранить данные; выбор получателя и дальнейшее обращение с ними остаются ответственностью пользователя. Автоматической отправки нет.
- Утрата до сохранения health marker при process kill/power loss не восстанавливается достоверно. Sync каждого append уменьшает окно, но не даёт невозможной гарантии. Ошибки заполненного диска моделированы I/O boundary; реальный ENOSPC и отключение устройства не воспроизводились.
- Logger рассчитан на один writer для одного log path в процессе. Зависший системный disk call может задержать drain; timeout сообщает отсутствие подтверждения. Startup disk read остаётся синхронным: P1-06 не объявлен исправленным этим этапом.
- Pending rotation требует ручной проверки. Неустранимые ошибки rollback видны как отказ; нельзя обещать атомарность всей последовательности rename при аварии процесса.
- Ручная приёмка на целевом телефоне, ShareSheet с реальным выбранным получателем, legacy logs пользователя и длительный нагрузочный прогон ещё впереди. Автотесты FileProvider не отправляют данные внешнему приложению.
