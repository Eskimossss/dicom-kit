# Инструкция: Версионирование и сборка тестовых APK DICOM Kit

Данный документ описывает правила версионирования, внедрённые метаданные сборки и регламент создания проверочных тестовых APK в проекте DICOM Kit.

---

## 1. Схема версионирования

В проекте используется семантическое версионирование (`MAJOR.MINOR.PATCH[-PRERELEASE]`) в сочетании с монотонно возрастающим целочисленным `versionCode`:

- **Текущая тестовая версия Worklist:**
  - `versionName = "1.5.0-alpha.2"`
  - `versionCode = 10502` (после `10501` в `1.5.0-alpha.1`; схема монотонного инкремента сохранена).
- **Идентификатор приложения:** `ru.medeng.dicomtool` (не изменяется).
- **Подпись приложения:** сохраняется существующая конфигурация release-подписи из `keystore.properties` / переменных окружения.

### 1.1. Регламент изменения версий
- `1.5.0-alpha.1`, `1.5.0-alpha.2`, `1.5.0-alpha.3`... — промежуточные сборки этапа разработки Worklist.
- `1.5.0-beta.1`, `1.5.0-beta.2`... — сборки этапа комплексного ручного тестирования перед релизом.
- `1.5.0` — стабильный официальный релиз после согласования и одобрения.

**Важно:** `versionCode` **не** увеличивается при каждом локальном запуске Gradle. Он инкрементируется разработчиком только при подготовке новой проверяемой сборки (например, `10501` -> `10502` для `alpha.2`).

## 2. Метаданные сборки и экран «О приложении»

В `app/build.gradle.kts` настроена автоматическая генерация полей `BuildConfig`:
- `BuildConfig.VERSION_NAME` — строковое имя версии (например, `"1.5.0-alpha.1"`);
- `BuildConfig.VERSION_CODE` — целочисленный код (например, `10501`);
- `BuildConfig.BUILD_TYPE` — тип сборки (`"debug"` или `"release"`);
- `BuildConfig.GIT_BRANCH` — имя активной ветки Git (например, `"feature/stage-7-worklist-mwl"`), либо `"unknown"`, если Git недоступен;
- `BuildConfig.GIT_COMMIT_SHA` — короткий хеш коммита (например, `"d205a1d"`), дополняемый суффиксом `"-dirty"` при наличии незакоммиченных изменений в рабочем дереве;
- `BuildConfig.BUILD_TIME` — дата и время сборки в UTC (например, `"2026-10-20 18:10:00 UTC"`);
- `BuildConfig.IS_GIT_DIRTY` — логический флаг чистоты рабочего дерева.

### 2.1. Доступ через интерфейс
1. В приложении перейдите в **Действия и настройки** (иконка шестерёнки в верхней панели).
2. Нажмите на строку **О приложении DICOM Kit**.
3. Откроется экран **О приложении**, отображающий параметры сборки, описание приложения и ссылку на разработчика.
4. По нажатию кнопки **«Копировать информацию о сборке»** все параметры сборки копируются в буфер обмена устройства для передачи в отчётах об ошибках или журналах тестирования.

## 3. Скрипт автоматизированной сборки тестового APK

Для сборки тестового APK одной командой подготовлен PowerShell-скрипт в корне репозитория:

```powershell
.\build-test-apk.ps1
```

### 3.1. Возможности скрипта
1. **Проверка окружения:** проверяет наличие `gradlew.bat` и настраивает `JAVA_HOME` (при необходимости).
2. **Определение версии:** автоматически считывает `versionName` и `versionCode` из `app/build.gradle.kts`.
3. **Проверка Git:** проверяет статус рабочего дерева. Если есть незакоммиченные изменения, скрипт прерывает выполнение, требуя чистое состояние для официальной тестовой сборки (либо явного флага `-AllowDirty`).
4. **Компиляция:** выполняет `assembleDebug` через Gradle Wrapper.
5. **Именование и размещение:** копирует собранный файл в каталог `builds/` с именем:
   `DICOM-Kit-<versionName>-debug.apk` (например, `builds/DICOM-Kit-1.5.0-alpha.1-debug.apk`).
6. **Защита от перезаписи:**
   - Если файл уже существует и его SHA-256 хеш совпадает, выводится уведомление.
   - Если файл уже существует, но собран из других исходников (хеш отличается), предыдущий файл архивируется с добавлением таймстемпа (`DICOM-Kit-<versionName>-<timestamp>-debug.apk`), предотвращая незаметную перезапись.
7. **Итоговый отчёт:** выводит полный путь к файлу, размер, версию, ветку, коммит и контрольную сумму SHA-256.

### 3.2. Примеры использования

Сборка из чистого рабочего дерева (рекомендуется):
```powershell
.\build-test-apk.ps1
```

Сборка из дерева с незакоммиченными изменениями (для быстрой локальной отладки):
```powershell
.\build-test-apk.ps1 -AllowDirty
```

Перезапись существующего APK без архивации:
```powershell
.\build-test-apk.ps1 -Force
```
