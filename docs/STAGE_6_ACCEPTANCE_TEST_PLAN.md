# Этап 6 — ручная приёмка Android

Проверять новый обычный debug APK этапа 6, точный SHA-256 указан в STAGE_6_RESULT.md и рядом с APK. Обновить поверх установленной версии, без очистки данных. Использовать отдельный тестовый каталог и исключительно синтетические объекты. Main пока не изменять. Это дополнение к ANDROID_ACCEPTANCE_TEST_PLAN.md.

1. **История и журнал.** Старые записи открываются; сохранены SCU/SCP-метки, направление, узел/порт/операция/длительность и цвета. В краткой карточке нет дублирующей строки «Результат». Передать в одном сеансе 1, 2 и 3 разных синтетических пациентов; проверить PN с пустыми компонентами/альтернативной группой, раскрытие списка, поиск по фамилии/имени/отчеству/полному имени. C-ECHO без пациента. Экспорт/копирование по умолчанию не содержит имён/ID; полный экспорт только после явного предупреждения. Не считать его эвристическую маскировку анонимизацией.
2. **SCP.** ECHO и несколько STORE в одной ассоциации, нормальное завершение release. В кратком журнале видны сохранённые файлы; в подробном различаются storage и запись RSP. Прервать синтетическую ассоциацию при ответе; не должно возникать заявления о получении RSP удалённым узлом. Bxxx/отказ хранения/partial не выдаются за полный Success. При отсутствии RSP проверить обе стороны, не делать вывод о его неполучении по одному local write.
3. **Диагностика архива.** Добавить в тестовую папку повреждённый synthetic.dcm; ошибка только в «Принятых», стадия/безопасная причина в деталях. Два одинаковых basename в разных путях не теряются. Повторный refresh не множит счётчик. После удаления/замены исправным синтетическим источником счётчик убывает. Charset warning не увеличивает read-error count. X скрывает плашку, постоянная кнопка диагностики остаётся.
4. **Viewer на планшете.** Из Принятых и Тегов открыть один синтетический объект: одинаковая рабочая область, слева изображение, справа «Просмотр и WW/WL» / «DICOM-теги». Нет «DICOM/Авто Мин-Макс/Enhance MAM» пресетов. Проверить search/copy/private/SQ, исходные WW/WL и LUT/rescale. Навигация находится на изображении.
5. **Viewer на телефоне.** Повторить в узком портретном и альбомном режиме, увеличить системный шрифт: нет горизонтально обрезанных кнопок/перекрытия нижней навигации. Панели прокручиваются, кнопки toolbar внутри viewport переносятся по строкам. Проверить полноэкранный режим, системный Back и повторное открытие без переключения на другой источник.
6. **Кадры и экземпляры.** Серия из нескольких однофреймовых объектов, отдельный multiframe, затем несколько multiframe в одной серии. Переключение «кадр» не должно переключать «снимок», доступны оба уровня. В многофреймовых enhanced-файлах применяется окно выбранного кадра.
7. **Живой WW/WL.** Открыть синтетическое 4000×3000 изображение. Медленно и быстро двигать WW/WL без отпускания пальца: изменение видно до release, нет долгой очереди старых окон после отпускания. После zoom/pan/inversion/frame change нажать «Сбросить WW/WL»: меняется только окно. «Сброс вида» отдельно сбрасывает окно/zoom/pan/inversion. SHA-256 оригинала до/после одинаков. Долго просматривать MONOCHROME1/2 и несколько больших объектов; отсутствие OOM/заметного накопления памяти проверить на телефоне.
8. **Уведомления.** C-ECHO/C-STORE success исчезает примерно через 6 секунд и закрывается X раньше. Error/warning спустя 10 секунд остаётся до X. После X результат операции/файла, записи журнала и metadata сохранены. Перейти между вкладками/повернуть экран: закрытая плашка не возвращается; повторить такое же событие — появляется новая. Закрыть charset notice, проверить теги и диагностику. Нажатие на warning журнала и отдельная кнопка состояния открывают подробности даже после X. Уведомление работающей foreground-службы Android имеет прежний жизненный цикл.
9. **Кодировки генератора.** Только тестовые пациенты. UTF-8 — default/ISO_IR 192; ISO-8859-5 — ISO_IR 144 и кириллица; ASCII — латиница без тега, кириллица блокирует STORE с понятным сообщением без '?'. Исправить поля/вернуть UTF-8: STORE снова доступен. Перезапустить приложение: настройка сохраняется. После сохранённого ASCII стартовые кириллические поля требуют редактирования — не должны отправляться старые данные.
10. **Экспериментальные режимы.** Без объявления: UTF-8 bytes без 0008,0005, предупреждение для не-ASCII. CP1251: нестандартное предупреждение, raw CP1251 bytes, нет фиктивного ISO_IR 144. Независимым parser/hex проверить PN/LO и идентичный Pixel Data. Приём PACS не гарантирует корректное чтение нестандартного текста. Повтор STORE того же prepared object не меняет UID/bytes. Обычная SCU-пересылка исходников не использует настройку генератора.
11. **Регрессии 5.1–5.6.** Повторы одинакового/разного содержимого, сохранение обоих при UID collision, миграция/повтор после неудачного удаления источника, keep.txt при cleanup, видимость неактивных .part и восстановление без потери оригинала; batch partial/error/unknown/cancel/retry; background/SCP stop/restart, уведомление службы, холодный запуск. Пакетная отправка и длительный фон из предыдущей ручной приёмки остаются обязательными.

Записать модель телефона/API/OEM, SHA APK, шаги и наблюдаемые статусы обеих сторон. При неверных pixels/TS, потере источника, ложном Success, ANR/OOM или утечке данных остановить приёмку и сохранить воспроизведение на синтетике. Реальные DICOM не прикладывать к публичным материалам. После результатов — отдельное решение пользователя о merge.
