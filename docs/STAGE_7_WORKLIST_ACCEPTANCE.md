В Storage SCP он может возникнуть при обработке/чтении заголовка, неуспешном сохранении или отклонении точного повтора политикой REJECT_IDENTICAL. Последний сценарий воспроизведён Android-тестом настоящего C-STORE; это не доказывает причину прежних пользовательских событий. Точная причина требует соответствующего события с Reason/Exception/Storage Result и сопоставления по сеансу/Message ID/SOP UID. Исходные скриншоты и технические записи ручной приёмки не были приложены, поэтому историческая причина **не установлена**. Не считать ошибку 0x0110 доказательством успешной передачи и не менять данные для её сокрытия.

## 1. Сценарий: Запуск локального MWL SCP и запрос с оборудования / утилиты DCMTK

### Шаг 1. Настройка и запуск MWL SCP на телефоне / планшете
1. Откройте приложение DICOM Kit и перейдите на вкладку **Worklist** (нижняя панель навигации).
2. Выберите подвкладку **Сервер (SCP)**.
3. Проверьте параметры:
   - **Local AE Title:** по умолчанию `DICOMKIT_MWL` (при необходимости измените на AET, ожидаемый вашим аппаратом).
   - **TCP Port:** по умолчанию `11112` (убедитесь, что порт свободен и не конфликтует со Storage SCP на 11104).
   - **Кодировка:** выберите требуемую аппаратом (`ISO_IR 192 (UTF-8)` или `ISO_IR 144 (Cyrillic)`).
4. Нажмите кнопку **Запустить MWL SCP**.
5. Убедитесь, что статус изменился на **РАБОТАЕТ (RUNNING)** зелёного цвета, отображаются сетевые интерфейсы устройства (например, Wi-Fi IP `192.168.1.50`), а в шторке уведомлений Android появился постоянный foreground-сервис «DICOM Kit MWL SCP активен».

### Шаг 2. Создание тестовых назначений
1. Перейдите на подвкладку **Назначения**.
2. Нажмите кнопку с иконкой мастера (или **Синтетические данные**).
3. В появившемся диалоге:
   - Выберите шаблон аппарата: например, **Рентген ОГК (CR/DX)** или **Компьютерная томография (CT)**.
   - Выберите режим: **Несколько пациентов** (создаст 3 тестовых пациента).
   - Нажмите **Создать**.
4. В списке назначений появятся созданные карточки пациентов со значком `Синтетическое`.

### Шаг 3. Запрос Worklist с медицинского аппарата или утилиты findscu
На аппарате или внешнем ПК с DCMTK выполните команду (подставив IP телефона):

```bash
findscu -v -W -k 0010,0010 -k 0010,0020 -k 0008,0050 -k "0040,0100[0].0008,0060" 192.168.1.50 11112 -aec DICOMKIT_MWL -aet MY_MODALITY
```

**Ожидаемый результат на аппарате/консоли:**
- `Association Accepted`.
- Получены записи назначенных исследований с ФИО, Accession Number и Modality.
- Завершение со статусом `Status: Success (0x0000)`.

**Ожидаемый результат в DICOM Kit:**
- На вкладке **Сервер (SCP)** в блоке «Подключенные узлы» отображается `MY_MODALITY`, число запросов увеличилось.
- На вкладке **Журнал** зафиксированы события ассоциации `A-ASSOCIATE-RQ/AC`, запрос `C-FIND-RQ`, ответы `C-FIND-RSP (Pending)` и финальный `C-FIND-RSP (Success)`.

## 2. Сценарий: Диагностика внешнего MWL-сервера (MWL SCU)

1. В приложении DICOM Kit перейдите на подвкладку **Клиент (SCU)**.
2. В блоке профиля выберите или создайте профиль удалённого сервера:
   - **Имя:** Тестовый RIS
   - **Host:** IP-адрес сервера (или `127.0.0.1` для локального теста)
   - **Port:** TCP-порт сервера (например, `11112` или `104`)
   - **Called AE Title:** AE Title удалённого сервера
   - **Calling AE Title:** AE Title нашего клиента (по умолчанию `DICOMKIT_SCU`)
3. Задайте фильтры поиска:
   - **Модальность:** например, `CT` или оставьте пустым для всех.
   - **Дата:** `Сегодня` или `Любая`.
4. Нажмите кнопку **Получить Worklist**.
5. При необходимости прервать длительный запрос нажмите **Отменить**.

**Ожидаемый результат:**
- Появится список полученных назначений с модальностями, именами пациентов и процедурами.
- При нажатии на карточку назначения открывается подробный просмотр:
  - Клинический блок (ФИО, пол, дата рождения, процедура, врач, кабинет).
  - Технический блок DICOM (полное дерево тегов, VR, вложенная последовательность `(0040,0100)`).
  - Кнопка копирования значений тегов.

## 3. Сценарий: Проверка белого списка (Calling AE Whitelist)

1. На вкладке **Сервер (SCP)** включите переключатель **Белый список Calling AE**.
2. Введите список разрешённых AE: `TRUSTED_AET, MODALITY_01`.
3. С внешнего узла отправьте запрос с AE Title `STRANGER_AET`:
   ```bash
   findscu -v -W 192.168.1.50 11112 -aec DICOMKIT_MWL -aet STRANGER_AET
   ```
4. **Ожидаемый результат:** запрос отклонён сервером (`A-ASSOCIATE-RJ`, Calling AE Title not recognized). В журнале появится запись об отклонении.
5. Отправьте запрос с AE Title `MODALITY_01`:
   ```bash
   findscu -v -W 192.168.1.50 11112 -aec DICOMKIT_MWL -aet MODALITY_01
   ```
6. **Ожидаемый результат:** ассоциация успешно принята, список выдан.

1. Перейдите на подвкладку **Журнал**.
2. Убедитесь, что отображаются записи с метками `MWL SCP-*` и `MWL SCU-*`.
3. Нажмите на любую запись журнала:
   - Проверьте отображение технических деталей (SOP Class, Transfer Syntax, Association ID, PDU, Returned Items).
4. Нажмите кнопку **Экспорт отчёта**:
   - По умолчанию переключатель «Включать ФИО пациентов (PHI)» выключен.
   - Убедитесь, что в сгенерированном отчёте персональные данные заменены на `***MASKED_PHI***`.
   - Скопируйте отчёт в буфер обмена для отправки техподдержке.
