## 1. Введение и цели этапа

Цель этапа **4.3.2** — трансформация технического журнала DICOM Kit в специализированный диагностический инструмент для сервисных инженеров медицинского оборудования:
- Внедрение двух согласованных режимов отображения (**«Краткий»** и **«Подробный»**).
- Реализация локального офлайн-справочника типовых сетевых и DICOM-ошибок с рекомендациями и чек-листами.
- Корректная группировка параллельных и разнесённых во времени сеансов на базе `sessionUid` с безопасной обработкой устаревших логов.
- Расширенная фильтрация и контекстный поиск по всем атрибутам обмена.
- Механизм копирования и экспорта журнала с эвристическим маскированием персональных данных (ПДн / PHI) через системный Android Share Sheet.
- Сохранение высокой производительности интерфейса при работе с максимальной глубиной журнала (2000 записей).

## 2. Архитектура и реализованные компоненты

### 2.1. Два режима отображения (`DicomLogDisplayMode`)
В верхней части экрана размещён сегментированный переключатель:
- **Краткий режим (по умолчанию)**: отображает компактные карточки сеансов (`DicomSessionSummary`), сводящие воедино итог соединения: направление обмена, имя удалённого узла, тип операции (C-STORE / C-ECHO), число переданных файлов, итоговый статус и длительность сеанса.
- **Подробный режим**: хронологический список всех дискретных технических событий (TCP, PDU, DIMSE) с бейджами направлений, кодами категорий и статусами.
- **Сохранение состояния**: Выбранный режим фиксируется в [`DicomToolViewModel`](file:///E:/Dicomtool/app/src/main/java/ru/medeng/dicomtool/ui/viewmodel/DicomToolViewModel.kt) и сохраняется при переходах между вкладками нижней навигации.

### 2.2. Модель сеанса и алгоритм группировки (`DicomSessionGrouper`)
Созданы модели в файле [`DicomSessionSummary.kt`](file:///E:/Dicomtool/app/src/main/java/ru/medeng/dicomtool/data/logging/DicomSessionSummary.kt):
- **`DicomSessionSummary`**: агрегирует `sessionUid`, `associationId`, `direction`, `role` (SCU / SCP / SYS), `primaryOperation`, `status` (`SUCCESS`, `FAILURE`, `WARNING`, `IN_PROGRESS`, `UNKNOWN`), параметры удалённого хоста, список файлов [`TransferredFileItem`](file:///E:/Dicomtool/app/src/main/java/ru/medeng/dicomtool/data/logging/DicomSessionSummary.kt), тайминги и диагностические рекомендации.
- **Интеллектуальная группировка**:
  1. События с современным `sessionUid` (например, `SCU-R123-0001` или `SCP-R123-0001`) объединяются в строгом хронологическом порядке без смешивания параллельных сетевых потоков.
  2. Предваряющие события установки сокета (`TCP-R...`) автоматически связываются с соответствующей ассоциацией SCP по сокету удалённого клиента (`remoteIp:remotePort`), исключая появление фиктивных «пустых» сеансов.
  3. **Безопасная обработка старых записей**: для логов до этапа 4.3.1 с пустым `sessionUid` применяется алгоритм разделения по границам ассоциаций (`ASSOCIATE_RQ`, `RELEASE_RP`, `TCP_DISCONNECT`, `ABORT`) и тайм-аутам, предотвращающий ложное слияние записей разных сессий и запусков приложения.
  4. Если соединение завершилось без однозначного признака успеха/ошибки, выставляется статус `UNKNOWN` («Результат неизвестен»), а не ложная «Ошибка».
  5. Для незавершённых сессий отображается статус `IN_PROGRESS` («Выполняется...»).
  6. При отсутствии ответа сервера статус формулируется как «Не получено подтверждение отправки (C-STORE-RSP не получен)», исключая ложный вывод об отклонении файла принимающим PACS.

### 2.3. Локальный справочник ошибок (`DicomDiagnosticHandbook`)
В файле [`DicomDiagnosticHandbook.kt`](file:///E:/Dicomtool/app/src/main/java/ru/medeng/dicomtool/data/logging/DicomDiagnosticHandbook.kt) реализован полностью офлайн диагностический анализатор, сопоставляющий события с известными паттернами:
1. `Connection refused (ECONNREFUSED)` — служба не запущена / закрыт порт файрволом.
2. `Connection timeout (ETIMEDOUT)` — неверный IP / изолированный VLAN / потеря пакетов.
3. `Socket read timeout` — зависание обработки на PACS / обрыв Wi-Fi.
4. `Connection reset (ECONNRESET)` — сброс сессии сервером или сетевым экраном.
5. `Unknown host / DNS error` — ошибка разрешения доменного имени.
6. `A-ASSOCIATE-RJ` — отказ в ассоциации с разбором источника, причины и рекомендациями по сверке Calling/Called AE Title.
7. `A-ABORT` — аварийный разрыв ассоциации.
8. Отсутствие согласованного Presentation Context.
9. Несовместимый Transfer Syntax (сжатие, Explicit vs Implicit).
10. Ошибочный ответ C-ECHO-RSP.
11. Ошибочный ответ C-STORE-RSP с детальной расшифровкой статусов DICOM:
    - `0x0000` (Success)
    - `0x0001`, `0xB000`, `0xB006`, `0xB007` (Предупреждения коэрциции/отброса тегов)
    - `0x0111` (Duplicate SOP Instance)
    - `0x0122`, `0x0124`, `0x0211` (SOP Class Not Supported / Not Authorized / Unrecognized Op)
    - `0xA700..0xA7FF` (Out of Resources / переполнение диска)
    - `0xA900..0xA9FF` (Data Set does not match SOP Class)
    - `0xC000..0xCFFF` (Processing Failure / внутренняя ошибка архива)
12. Таймаут C-STORE-RSP (отсутствие ответа).
13. Ошибка чтения файла (доступ SAF / повреждённый файл).
14. Ошибка сохранения файла SCP (переполнение дискового пространства).

Каждая рекомендация включает:
- Техническое наименование ошибки.
- Простое объяснение на русском языке.
- Список вероятных причин.
- Пошаговый чек-лист действий сервисного инженера.
- *Для неизвестных ошибок не генерируются выдуманные причины — отображаются только исходные параметры.*

### 2.4. Раскрытие карточек и событий
- **В кратком режиме** раскрытая карточка показывает:
  1. Общую информацию о сеансе (ID сеанса, Calling/Called AE Title, сокет, время, продолжительность).
  2. Список переданных/принятых файлов с индивидуальными статусами.
  3. Технические параметры ассоциации (SOP Class, Transfer Syntax, размеры PDU, версии реализаций).
  4. Блок диагностических рекомендаций (при наличии ошибок/предупреждений).
  5. Полную хронологию шагов соединения с временными метками.
  6. Кнопку быстрого копирования всего сеанса в буфер обмена.
- **В подробном режиме** раскрытая запись показывает таблицу сырых технических параметров и диагностическую карточку при наличии сбоя.

### 2.5. Фильтрация и поиск
- **Направление**: `Все` | `SCP IN` | `SCU OUT`.
- **Результат**: `Все` | `Успешно` | `Ошибки` | `Предупреждения` | `Выполняется / неизвестно`.
- **Полнотекстовый поиск**: поиск без учёта регистра по AE Title, IP-адресу, порту, имени файла, UID сеанса/файла, кодам статусов (0x...) и тексту заголовков/деталей.
- Фильтры работают согласованно в обоих режимах отображения.

### 2.6. Копирование и экспорт с защитой ПДн
- Быстрое копирование отдельного события или сеанса в буфер обмена с уведомлением.
- Диалог экспорта через системный Android Share Sheet:
  - **Без персональных данных (по умолчанию)**: алгоритм [`DicomLogExportUtils`](file:///E:/Dicomtool/app/src/main/java/ru/medeng/dicomtool/data/logging/DicomLogExportUtils.kt) выполняет эвристическое маскирование атрибутов `PatientName`, `PatientID`, дат рождения (`YYYYMMDD` и `DD.MM.YYYY`) и полей пациента.
  - **Полный технический журнал**: исходные параметры без изменений.
  - Интерактивный предпросмотр формируемого файла в окне диалога.
  - Экспорт не модифицирует оригинальные записи в памяти устройства и базе данных.
  - Настроен [`FileProvider`](file:///E:/Dicomtool/app/src/main/AndroidManifest.xml) и [`file_paths.xml`](file:///E:/Dicomtool/app/src/main/res/xml/file_paths.xml) для безопасного предоставления URI временных файлов приложению-получателю.

### 2.7. Оптимизация производительности
- Вычисление агрегированных сеансов выполняется в фоновой корутине через реактивный оператор `combine` в `DicomToolViewModel`, исключая тяжелые вычисления при recomposition.
- Списки отрисовываются через `LazyColumn` со стабильными строковыми ключами.
- Отключена автопрокрутка на каждый промежуточный сетевой пакет в кратком режиме.
- Тест на 2000 записей подтверждает группировку и фильтрацию менее чем за 100 мс.
