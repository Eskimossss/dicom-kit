Предыдущие исправления и незакоммиченные изменения сохранены.

Верхняя сводка строится по реальным полям LoggerHealth. Любой счётчик потерь, неподтверждённых событий, отказов или ошибок, последняя ошибка, незавершённая ротация и состояния DEGRADED/WRITE_FAILED исключают вывод «работает нормально», даже при ACTIVE. При отсутствии этих признаков отдельно показываются загрузка истории, остановка/остановлен и незавершённая запись (очередь либо принято больше, чем записано). Только оставшийся нормальный случай получает сообщение об отсутствии обнаруженных потерь. Это описание доступной диагностики, а не гарантия сохранения очереди при аварии.

Все пять состояний локализованы: ACTIVE → «Активен», DEGRADED → «Сбои или потери», WRITE_FAILED → «Ошибка записи», STOPPING → «Останавливается», STOPPED → «Остановлен». Логические значения — «Да» / «Нет». Исходные `state`, `historyLoading`, `rotationPending`, остальные поля и сообщение последней ошибки доступны в раскрываемом разделе «Исходные технические значения», без изменения оригинала.

| Блок | Показатели и семантика |
|---|---|
| Общее состояние | Текущее состояние и сводка диагностики |
| Запись событий | Принято в очередь, успешно записано, ожидает в очереди без текущей записи, сброшено при переполнении (отдельно некритические/критические), запись не подтверждена и критическое подмножество |
| Ошибки и ограничения | Ошибки чтения, события/критическое подмножество, отклонённые после начала остановки; ошибки, тайм-ауты и отказы **управляющих операций** журнала |
| Дополнительная диагностика | Незавершённая ротация, загрузка истории, последняя ошибка, исходные технические значения |

Принято/записано относятся к событиям текущего процесса; сведения о потерях могут включать восстановленную историю. Это не счётчики DICOM-файлов. Критические значения — подмножества общих, не добавочные потери. «Не сохранено при переполнении» = droppedNormal + droppedCritical, отказы после начала остановки показаны отдельно. Итоговая сумма отображается точно даже при синтетических значениях Long.MAX_VALUE, без переполнения; решения о состоянии не используют потенциально переполняемые суммы. Сами значения LoggerHealth не пересчитываются и не сбрасываются.

Подписи и значения выровнены в две колонки, строки переносятся, всё содержимое прокручивается, кнопка «Закрыть» остаётся вне прокрутки. Диалог использует палитру MaterialTheme и проверен с обеими палитрами. Общая тема приложения остаётся принудительно светлой; глобальное включение тёмного режима не входило в это дополнение.

## Повторная проверка замечаний с телефона — 15.10.2026

Отзыв пользователя относится к кандидату a436c2d; это частичная ручная приёмка. Новые изменения требуют повторного теста на телефоне. Пакетная отправка и длительный фон пока не приняты окончательно.

1. На каждой основной вкладке: первый Back показывает подсказку, второй в течение 2 секунд закрывает Activity. После паузы более 2 секунд снова нужна пара. Из настроек/Viewer сначала обычный возврат; закрытие Activity не означает остановку SCP-службы.
2. Отправить один синтетический файл трижды в каждом режиме повторов. Проверить реальные C-STORE-RSP, число файлов в «Принятых» и запись о способе хранения; разные Pixel Data того же UID всегда должны сохраняться.
3. Включить «ФИО + UID для папок новых исследований». Новый синтетический пациент с кириллицей получает очищенное ФИО и UID; новый экземпляр уже существующего исследования остаётся в старой папке. Выключение настройки тоже не переименовывает архив.
4. Выполнить очистку в отдельном тестовом SAF root: DICOM-файлы, принадлежащие приложению, удалены; keep.txt, неизвестные документы и директории сохранены. Пустые SAF-папки могут оставаться намеренно.
5. При активном приёме нет ложного предупреждения об оставленном .part. После прерывания/ошибки оставшиеся неактивные файлы видны отдельно. В настройках явно запустить «Повторить сохранение входящих файлов»: допустимые источники копируются с проверкой, непроверенные остаются, повтор не множит копии. Не удалять телефонные .part вручную, пока не выяснено их содержимое. Структурный разбор и hash копии не доказывают полноту первоначальной передачи без сверки с отправителем.
6. Во встроенном и полноэкранном Viewer проверить WW−/WW+ (контраст), WL−/WL+ (яркость), шаг около 5% текущего WW и пределы диапазона. «Авто Мин/Макс (WW/WL)» вычисляется по значениям кадра, DICOM-пресет берётся из тегов. SHA исходника не меняется.
7. Выполнить C-ECHO и отключиться: узел остаётся в истории до остановки сервера; следующий запрос обновляет время, а не создаёт вторую строку. Active connections отражает действующие сокеты, история не означает ONLINE. Новый запуск очищает историю.
8. Экспортировать краткий безопасный журнал нескольких параллельных сеансов: метки SCP-N/SCU-N и локальная нумерация сеансов экспорта позволяют сопоставление; ФИО/AE/IP/пути/UID экземпляров не возвращаются в безопасный экспорт. Это не гарантия юридической анонимизации.
